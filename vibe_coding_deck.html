Project One

Lab52 庫存系統

從散落的 Excel 和 HTML，到一個統一的管理介面

庫存系統 · 需求

我想要什麼

原始資料狀態：

  • 倉庫每月匯出一個 HTML 報表
  • FBA 庫存在 Seller Central，無法自動拉取
  • 台灣倉出入庫靠人工記錄
  • 批次效期、在途貨件沒有統一追蹤

「我要一個地方，
讓我一眼看到所有倉的狀況。」

我定義的功能邊界

模組解決什麼
海外倉庫存批次、效期、箱數、位置
台灣倉獨立出入庫紀錄，流水帳餘量
FBA 庫存自動同步水位 + 日均銷量
在途追蹤出貨到到貨的全程狀態
帳單倉儲費用記錄
庫存系統 · 過程

過程中遇到什麼，怎麼克服

架構換了一次

第一版用 Node.js + 本機伺服器，跑起來了，但有個根本問題：需要一直開著電腦，其他人看不到資料。

→ 第 8 天決定整個搬到 Google Apps Script，後端變成 Google Sheets，任何人開連結就能用。

FBA 銷量會被庫存同步覆蓋

庫存每小時同步一次，但銷量每週才更新一次——每次同步都會把銷量欄清空。

→ AI 設計「欄位責任分離」：hourly sync 只碰庫存欄，銷量欄另外保留。

關鍵洞察

第一版的 7 天不是浪費。

那 7 天是用來弄清楚「我真正需要什麼」。帶著這些業務邏輯重建更好的底層，比第一次就想正確快得多。

技術坑的處理方式

過程中踩了 SQLite 的 6 個限制、GAS standalone 的 API 限制、SP-API 的 oauthScopes 問題——這些都是 AI 的工作，不是我需要懂的事。

現在可以做到什麼

Influencer Tracker · 設計決策

我做的設計決策（每一個來自真實需求）

自動待辦引擎

每天開啟，自動比對所有 KOL 資料，生成當天要做的事。7 種觸發規則，14 天前的舊案件自動隱藏。

Sidebar 設計成唯讀

點開待辦，右側滑出 KOL 的聯絡方式和 Timeline。這裡只能看，不能改——因為「快速拿到聯絡方式」和「編輯資料」是兩件不同的事，不能混在一起。

今日已處理，不寫回 Sheets

勾選「今天已催腳本」只存在瀏覽器本機。因為「我今天發了訊息」不是資料狀態的改變，隔天 KOL 沒交稿，提醒還是要出現。

狀態點擊循環切換

Posts 日曆的色點，一次點擊循環切換 5 種狀態並即時寫回 Sheets。因為「我只是想標記這篇排程了，不想做其他事。」

美國假日自動標注

我說「排貼文要看到節慶」，AI 自己實作了浮動假日算法（第 n 個週幾），不是硬寫日期。

範本變數橘色高亮

DM 範本裡的 [Name]、[video] 自動標橘色。複製貼上時不會漏改到 [Name]。

Influencer Tracker · 成果

現在可以做到什麼

組員每天開啟看到的

  • 今天要付哪筆款
  • 3 天內要催哪些腳本 / 初稿
  • 哪位 KOL 今天要確認上線
  • 有哪些 follow-up 跟進提醒

不需要翻 Sheets，不需要靠記憶。

Web 上改的東西，直接回寫 Sheets

8 個寫回函數，Timeline 日期、KOL 狀態、貼文排程、外發紀錄——全部即時同步，不需要再開 Sheets 操作。

多人協作，零設定

部署在 GAS，有連結就能開，讀寫同一份 Sheets。不需要帳號系統，不需要額外設定。

這套工具解決的核心問題：
讓組員把時間花在「跟 KOL 溝通」，
而不是「找資料」和「記有沒有催過」。

Methodology

Vibe Coding 方法論

從這兩個專案提煉出來的五個原則

方法論

五個讓 Vibe Coding 有效的原則

1. 先跑起來，再修問題

不花時間在前期完美選型。真實踩到的問題比預想的問題更具體、更有解。

2. 業務邏輯由人決定，工程實作交給 AI

幾天前觸發提醒、哪些欄位必填、Sidebar 要唯讀還是可編輯——這些問題 AI 無法替你決定，也不應該決定。

3. 架構決策是里程碑，不是失敗

Node.js → GAS 的轉換看起來是重做，實際上是帶著第一版學到的業務邏輯，建更好的底層。

4. 問題紀錄即文件

遇到的技術限制記入 AI memory。下次對話的 AI 不需要重新踩一遍，協作是有記憶的。

5. 用成本約束來選架構

「月費 $0」不是附加需求，是硬性約束。這個約束直接導向 GAS，而不是 Firebase / Vercel / Supabase。

技術是手段，不是門檻。
懂業務的人才是最好的產品設計師。
方法論

人與 AI 的實際分工

我決定的

需要哪些功能模組
哪些欄位、哪些分頁要存什麼
幾天前觸發提醒才合理
Sidebar 要唯讀還是可編輯
IG DM 一鍵跳轉連結
美國假日要標注在日曆
月費 $0 是硬性要求

AI 決定的

CORS 問題用 JSONP 繞過
GAS standalone 的 API 限制與解法
node-sqlite3-wasm 六個限制逐一排除
SP-API 的呼叫方式與 oauthScopes
浮動假日算法（第 n 個週幾）
主動加入 XSS 過濾和 URL 驗證
hourly vs weekly sync 欄位責任分離

我沒有要求安全防護，AI 自己加了。我說「這個選擇器太醜了」，AI 重做了一個跟整體設計一致的版本。
